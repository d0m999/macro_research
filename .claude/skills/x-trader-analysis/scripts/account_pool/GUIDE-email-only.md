# X 纯邮箱注册增强 SOP（无手机号路径）

> 适用场景: 你只有邮箱，没有可用的手机号（实卡或虚拟号都没有）。
> 目标: 把 X 注册成功率从基线 50% 拉到 **70-80%**，并把入池后存活率从 30% 拉到 **60%+**。
> 配套阅读: `GUIDE.md`（主 SOP，覆盖手机号方案）+ `README.md`（FAQ）。

---

## 心智模型（必读 1 分钟）

X 风控对**纯邮箱号**有特殊敌意，因为它把手机号当作"唯一可信的人类指纹"。但只要把以下三件事做对，仍然能稳定养出 3-5 个号:

1. **邮箱要"老"**: 新注册的 Gmail 注册 X 通过率 < 20%；用了 1-3 个月的 Gmail 通过率 60-80%
2. **行为要"真"**: 注册前后 1 小时的鼠标轨迹、停留时长、操作节奏都被 X 静默观察
3. **要有"备货"**: 默认假设 50% 注册失败 + 40% 入池后短期阵亡 → 想要 5 个长期可用的号，至少备 10-15 个邮箱起步

跳过任何一条，结果会很惨。如果上面三条任何一条做不到，老实回去看主 GUIDE.md 用手机号方案，或者走 Apify 兜底（`make scrape-apify`）。

## Part 1: 邮箱准备（决定 70% 通过率的关键）

### 1.1 邮箱选型（铁律）

| 邮箱 | 纯邮箱注册通过率 | 备注 |
|---|---|---|
| **Gmail（独立账号，用过 1-3 个月）** | **70-80%** | **唯一推荐** |
| Gmail（刚注册 <1 周） | 15-25% | X 能识别新 Gmail，拒绝率高 |
| 自建域名邮箱（Cloudflare Email Routing / Fastmail） | 50-70% | 仅次于老 Gmail |
| iCloud | 25-40% | 不要用 + 别名 |
| Outlook / Hotmail | 20-30% | X 风控敌意明显 |
| ProtonMail / Tutanota | < 5% | 几乎直接拒绝 |
| 临时邮箱 | < 1% | 一律拒绝 |
| QQ / 163 | 15-25% | 海外 IP 注册时通过率略升 |

**结论**: 准备 5-10 个独立 Gmail 账号。

### 1.2 Gmail "老化"（拉通过率最高 ROI 的动作）

X 在注册时会检查邮箱的"可信度"。一个被真实使用过的 Gmail 比新 Gmail 通过率高 3-4 倍。

**方法**: 注册 X 之前 **1-3 个月**，让每个 Gmail 做以下"真人活动":

- [ ] 发送 / 接收 ≥10 封正常邮件（不要全是给自己发）
- [ ] 订阅 2-3 个 newsletter（TechCrunch / The Verge / Substack 任意）
- [ ] 在登录态下 Google 搜索过 ≥20 次
- [ ] 登过 YouTube 看过几个视频
- [ ] 登过 Google Drive 创建过 1 个文档
- [ ] 偶尔登 Gmail Web 端（不是只用 IMAP/客户端）

**最低标准**: 至少满足前 4 条，且 Gmail 注册满 1 个月。**别为这点跳过**——一个新 Gmail 几乎注定让你浪费 IP 和时间。

如果你现在邮箱都没养过 → 走两条路:
- **路径 A（推荐）**: 今天先注册 5-10 个 Gmail，正常使用 1 个月，期间任务搁置。1 个月后回来按本 SOP 注册 X
- **路径 B（速成）**: 直接用 Apify 兜底（`make scrape-apify`），跳过自养号

### 1.3 IP 准备（同等重要）

纯邮箱注册时 X 对 IP 异常敏感。规则:

| IP 类型 | 纯邮箱通过率 |
|---|---|
| 家用 WiFi（住宅 ISP） | 60-80% |
| 手机 4G/5G 热点 | 50-70% |
| 公共 WiFi（咖啡店 / 图书馆） | 40-60% |
| 商业 VPN（NordVPN / ExpressVPN 共享 IP） | 5-20% |
| 数据中心 IP（AWS / DigitalOcean / 阿里云） | < 5% |
| Tor 出口节点 | 0% |
| 住宅代理（Bright Data / IPRoyal） | 60-80%（贵） |

**关键**: 注册纯邮箱号时**关掉所有 VPN/代理**。X 检测到 VPN/数据中心 IP，会直接强制要求手机号。

### 1.4 浏览器准备

- 用 Chrome 或 Edge（X 对它们的指纹最熟悉）
- **独立 user-data-dir**（见主 GUIDE.md Part 1.4）
- 不要装：广告拦截器、隐私工具、爬虫扩展、user-agent 切换器
- 可以装：少量常见扩展（密码管理器 / 翻译）让指纹看起来"正常"

### 1.5 时段选择

X 风控强度在不同时段有差异（社区观察，非官方）:

- **最佳**: 美东 / 美西工作时间（北京 21:00 - 次日 06:00）
- **次佳**: 欧洲工作时间（北京 15:00 - 23:00）
- **较差**: 亚洲深夜批量注册时段（北京凌晨 2-5 点）—— 这个时段亚洲 bot 农场活跃，X 风控加强

## Part 2: 注册流程（关键改动）

### 2.1 注册前清场（必做）

1. 关闭所有 VPN / 代理
2. 用真实家用 WiFi（不要用手机数据 + WiFi 共享）
3. 启动独立 Chrome profile（`--user-data-dir=$HOME/.x-profiles/u1`）
4. **第一步不要直接去 x.com**: 先 google `twitter alternatives` 之类的关键词，看 2-3 个结果，再访问 x.com（建立"我是真人随机浏览到这里"的指纹）
5. x.com 主页停留 30-60 秒，滚动看看，再点 Sign up

### 2.2 选邮箱路径

1. 点 "Sign up" / "Create account"
2. **关键**: 第一个弹出的表单默认是 phone，找下方 **"Use email instead"** 小字链接点它
3. 如果没有 "Use email instead" 选项：刷新 1-2 次重新进入（A/B 测试），仍然没有就换浏览器 profile

### 2.3 填资料（节奏控制）

| 字段 | 建议 | 节奏 |
|---|---|---|
| Name | 真人感名字（如 `Jordan Lee` / `张明`），别 `user_xxx` | 慢慢打，不要复制 |
| Email | 老 Gmail | 慢慢打 |
| Birthday | 25-40 岁随机 | 用 X 的 picker 选，不要直接打 |
| 整体填表时间 | **30-90 秒**，不要 5 秒填完 | 期间偶尔停顿 |

X 检测自动化的核心信号:
- 填表时间 < 15 秒 → 高度怀疑 bot
- 全程没有鼠标移动 → 怀疑
- 复制粘贴 Name/Email → 怀疑（手打值得 +20% 通过率）
- 用 Tab 切换字段 → 中等怀疑（最好用鼠标点）

### 2.4 邮箱验证码

1. X 发 6 位验证码到 Gmail
2. **注意**: Gmail 的 "Promotions" / "Updates" 标签经常吃 X 的邮件，记得检查
3. 收到后回到 X 表单填入，时间间隔 30-90 秒（不要 5 秒就回来填）
4. 设密码（12+ 位，混合）

### 2.5 关键拦截点处理

填完表后，X 在这一步会做一次"是否强制要求手机号"的决策。三种结果:

**结果 A**: 直接进入"完善 profile"流程 → 恭喜，闯过来了，跳到 Part 2.6

**结果 B**: 弹出 "We need to verify your account, please add a phone number"
- 操作: **立刻关浏览器**，不要点任何按钮
- 等待: 2-4 小时
- 重试: 完全清理浏览器 profile，换 IP（家用 WiFi → 手机热点），换 Gmail
- 不要做: 点 Skip / Cancel（会被标记），或硬刷"换个 Gmail 继续"（也会被标记）

**结果 C**: 弹出 arkose challenge（拼图 / 选物体）
- 操作: 老老实实手动做，做对就过
- 失败 3 次: 该号放弃，换 Gmail + 换 IP 重来

### 2.6 完善 profile（10 分钟内必做）

注册成功后，X 给你 ~1 小时的"观察窗口"，你的行为决定号能不能活过 24 小时。

**必做（10 分钟内）**:
- [ ] 上传头像（任何真实图片）
- [ ] 写 bio（30-80 字，crypto / 日常 / 兴趣相关都行）
- [ ] 关注 5-10 个真实账号（@elonmusk @VitalikButerin @cz_binance 等）
- [ ] 滚动 timeline 5 分钟
- [ ] Like 5 条不同账号的推文
- [ ] 发第 1 条原创推（`GM, market looks interesting` / `hello x`）

**强烈推荐（30 分钟内）**:
- [ ] 上传背景图
- [ ] 填位置（任何真实城市）
- [ ] Retweet 1 条
- [ ] 回复 1 条推文

**注意**: 不要登出，让 session 保持活跃 1 小时以上。

## Part 3: 注册后 7 天保活（决定 60% 存活率）

### 3.1 第 1 天（注册当天 + 0-24h）

注册后 1 小时:
- [ ] 完成 Part 2.6 必做和推荐项

注册后 6-12 小时:
- [ ] 再次登录浏览器，刷 5 分钟 timeline
- [ ] Like 3-5 条，Retweet 1 条

注册后 12-24 小时:
- [ ] 第 3 次登录，发 1 条推

**目标**: 第 1 天有 3 次独立 session 活动。

### 3.2 第 2-3 天

每天 2 次浏览器登录:
- 每次 5-10 分钟
- 滚 timeline + Like 5 条 + Retweet 1 条
- 第 2 天关注 5 个新账号
- 第 3 天发 1 条推

### 3.3 第 4-7 天

每天 1 次登录:
- 5 分钟活动
- 累计 6 条原创推 + 30+ Like + 5+ Retweet

### 3.4 第 7 天检测

满足下列才算"出关候选":
- [ ] 7 天内未收到过任何 "verify" 弹窗
- [ ] 关注 30+，原创推 6+，Like 30+
- [ ] Gmail 收件箱有 X 的"weekly recap" 邮件（说明 X 把你当活号统计）
- [ ] X 的设置页面 "Account Status" 显示正常

### 3.5 第 8-14 天

可以选:
- **保守路径**: 继续养到 Day 14 再入池（推荐，邮箱号需要更久）
- **激进路径**: Day 8 入池但**前 7 天只跑 50 请求/天**

邮箱号特别脆弱，强烈推荐保守路径。

## Part 4: 同 IP 多号策略

如果只有家用 WiFi 这一个 IP，怎么注册 5-10 个号?

### 4.1 节奏规则

- **Day 0**: 注册号 1
- **Day 2**: 注册号 2（间隔 48h，比手机号方案的 24h 更长）
- **Day 4**: 注册号 3
- **Day 6**: 注册号 4
- **Day 8**: 注册号 5

10 天注册 5 号，比 24h 内注册 5 号通过率高 3-5 倍。

### 4.2 多 IP 加速

如果能借多个 IP（家 + 手机热点 + 公司 + 朋友家），节奏可以加快:

- **Day 0**: IP A 注册号 1 + IP B 注册号 2（同时）
- **Day 1**: IP C 注册号 3
- **Day 2**: 间隔 24h 后，IP A 注册号 4

### 4.3 IP 黑名单管理

如果同 IP 注册失败 3 次以上 → 该 IP 至少冷却 1 个月再用。强行继续会让该 IP 进入更严格的风控池。

## Part 5: 入池后特殊保护（邮箱号专用）

邮箱号入池后，比手机号号需要更"小心":

### 5.1 强度限制

| 指标 | 手机号号 | 邮箱号 |
|---|---|---|
| 每天最大请求 | 500 | **200** |
| 每分片间抖动 | 5-15s | **10-30s** |
| 总并发账号数 | 3-5 | **2-3** |

修改 `scrape_twscrape.py` 调用时:
```bash
make scrape USER=ShanghaoJin SINCE=2023-01-01 UNTIL=2026-05-17
# 邮箱号池子建议加 --max 上限手动控制
```

### 5.2 保活动作

| 操作 | 手机号号 | 邮箱号 |
|---|---|---|
| 浏览器手动登录 | 每周 1 次 | **每周 2-3 次** |
| 每次手动操作时长 | 1 分钟 | **5 分钟** |
| 必做项 | 滚 timeline | **滚 + Like + 偶尔发推** |

### 5.3 监控频率

```bash
# 每 3 天跑一次（手机号号每周 1 次）
make account-health
```

异常号（cookies_bad / error）立刻 `--fix`，不要让坏号污染池子。

### 5.4 Cookies 更新频率

- 手机号号: 30 天重导一次
- **邮箱号: 14-20 天重导一次**（cookies 失效更快）

## Part 6: 失败友好工作流

**关键心态**: 失败是工作流的一部分。一个 5-号池子背后是 10-15 次注册尝试。

### 6.1 失败日志

每次注册（成功或失败）记一笔（推荐 `data/account_log.md`，本地，不提交）:

```
2026-05-20 14:30 | IP: 家用 | Email: u1@gmail.com | Profile: chrome-u1 | 结果: 注册中途要求手机 | 弃号
2026-05-20 16:00 | IP: 4G   | Email: u2@gmail.com | Profile: chrome-u2 | 结果: 注册成功 | 入池: Day 14
2026-05-22 10:00 | IP: 家用 | Email: u3@gmail.com | Profile: chrome-u3 | 结果: 注册成功但 Day 2 被锁 | 弃号
```

### 6.2 IP / 邮箱黑名单

- 同 IP 失败 3 次 → 30 天冷却
- 同 Gmail 失败后**不要复用**（X 已标记）
- 整个 Chrome profile 失败 → 完全删除 user-data-dir 重新创建

### 6.3 备货管理

任何时候保持:
- 已注册成功但未入池: 2-3 个
- 入池中且健康: 3-5 个
- 备用 Gmail（未注册 X 过）: 5+ 个

任何一项掉到下限 → 启动新一轮养号。

## Part 7: 故障速查表

| 现象 | 根因 | 处理 |
|---|---|---|
| Sign up 页面没有 "Use email instead" 链接 | A/B 测试 | 刷新 / 换浏览器 profile |
| 填完表弹 "We need to verify..." 要手机 | IP / 邮箱可信度低 | 关浏览器，2-4h 后换 IP + 换 Gmail 重试 |
| arkose challenge 反复出现 | 行为太机械 | 故意慢一点、滚动一下页面、操作前等 5 秒 |
| 注册成功 1 小时内被锁 | profile 太空 + IP 异常 | 弃号，下次注册立刻完善 profile |
| 注册成功，2 天内被要求 phone | 邮箱号特殊脆弱 | 弃号（救不回来） |
| 入池 1 周内 cookies_bad | 邮箱号早期阵亡 | 弃号，正常衰减 |
| 入池 2-4 周后 cookies_bad | cookies 过期 | 浏览器重登 → 重导 cookies |
| 抓取触发限流频繁 | 强度过高 | 降到 100-150 请求/天/号 |

## Part 8: 真实预期管理

按本 SOP 严格执行，你大概率会经历:

| 阶段 | 数量预期 |
|---|---|
| 准备的 Gmail 数 | 10-15 |
| 注册尝试 | 10-15 次 |
| 注册成功 | 7-10 个（70%） |
| 完成 14 天养号 | 5-7 个（其余在 Day 2-7 被锁） |
| 入池后 30 天仍活 | 3-5 个（其余在第 1 周阵亡） |
| 入池后 90 天仍活 | 2-4 个 |

**总投入**: 10-15 个 Gmail × 1 个月养邮箱 + 5-7 个号 × 14 天养号 = **6-8 周时间**，但绝大部分是被动等待，活跃操作 ≤ 2 小时/天 × 14 天 = 28 小时。

**对比手机号方案**: 14 天养号 + 7-10 天积累，活跃 1 小时/天 × 14 天 = 14 小时，且通过率 90%+。

**如果你觉得太麻烦**: 
- 走 Apify 兜底（`make scrape-apify`），一次性博主 $1-2，能跑 50-100 次（按月 1-3 博主算）= 几个月成本 $5-15
- 数学上 Apify 反而比养号便宜（如果你的时间值钱的话）
