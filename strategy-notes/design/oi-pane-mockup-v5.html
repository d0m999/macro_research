三层在说同一句话

V4 的五层里,L0 色雾、L1 方向柱、L3 事件车道编码的是同一组四元量(ΔOI 符号 / 价格符号 / |z| / 是否过门限)。不是「也有点冗余」——是字面意义上的同一个布尔表达式渲染三次。本稿用同一份 500 根真实数据先量化这件事,再按「每个通道装它擅长的量」重新分配,并排验证新方案没有重蹈覆辙。

01冗余证明(不靠论述,靠计数)

在当前参数下逐根统计三层各自点亮了哪些 K 线。若三层携带不同信息,这三个集合不应该相等。

下半区同理:L3 底部 ◆ vs L1 柱在零轴下方且过门限

三个数字 完全相等 ,且不是巧合——isVetoPaint 与 vetoEvt 在源码里是逐字相同的表达式(sp == 1 or sp == 3,分别在 :215 与 :245),色相规则也相同(sp == 1 ? colUp : colDn)。而 zClipEff = max(zClip, gateK) 保证了「柱尖越线 ⟺ 过门限」永不劈叉,于是 L1 的轴向 + 柱长 + 色相已经把这三层想说的话说完了。三层之间的互信息为 0。

02通道重分配

问题不在「砍哪一层」,在通道分配错了。每个视觉通道有它擅长的量;把同一个量塞进所有通道换来的不是冗余保险,是显著性通胀——每根 veto 同时用三个通道喊,面板就没有动态范围去区分 1.6σ 的边缘 veto 和 4σ 的极端 veto 了。

车道为什么改成密度带,而不是继续画离散标记。四状态近似均匀分布,于是「真值 veto」的占空比约 50%——500 根里每隔一根就有一个。若按离散 ✕ 画全集,等于把 v1 稿要治的「噪声墙」原样搬到车道上。密度带是同一个 Pine 原语(plotshape(location.top, shape.square, size.tiny)),但在高占空比下读作纹理而非事件:满饱和的方块从低饱和底纹里跳出来,眼睛读的是比例,不是逐个计数。

3 秒读法

  • 背景成片发蓝 = 4H 处于「跌+OI↑」区间 = 高周期层面新空在建仓,B多 这段时间整体别碰
  • 背景成片发白 = 4H「涨+OI↑」= 新多推动,B空 整段禁入
  • 亮柱越过 ±k 线 = 本周期过门限事件,读法与 V4 完全一致
  • 顶带满饱和方块 = 柱子点亮的那批;低饱和底纹 = 门限静音掉的硬 veto
  • 校准用法:拖 k 滑杆,看顶带里满饱和占比怎么变。满饱和太稀 = 门限过严,大量硬 veto 被吞;底纹几乎消失 = 门限过松,退化成纯符号模式

04自检:新方案有没有重蹈覆辙

既然本稿的全部论点是「两层不该说同一句话」,新方案就必须自证。用 Jaccard 相似度量化新色雾(4H 区间)与新车道(1h 真值 veto)点亮的 K 线集合重叠度——若接近 1,说明只是换了个说法继续冗余。

V4:色雾 ∩ 顶部✕ 的 Jaccard
—
两层点亮完全相同的 K 线集合。1.000 = 完全冗余,这是本稿要修的病。
V5:4H 色雾 ∩ 真值车道 的 Jaccard
—
两层各自独立发声。交集不为零是合理的——4H 与 1h 在同向时本就该共振,但远不是同一集合。
