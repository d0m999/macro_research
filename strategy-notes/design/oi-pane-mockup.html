这个面板判断的是一件事:这波行情是新仓推的,还是旧仓平的? 当前指标把回答这个问题的四个状态压进单一颜色通道逐根全饱和上色——真实数据下状态每 4 根翻转 3 次,结果是不可读的噪声墙。本稿先讲清判读原理,再用真实数据对比 3 个重设计方案,全部限定在 Pine v6 可实现的绘制原语内。

01原理:OI 在判断什么

这个面板不是「又一个指标」——它是一张 2×2 判读矩阵的渲染。要评审可视化,先得看懂这张矩阵在问什么。以下机制与规则语义全部取自 strategy-notes/strategy-01-mtf-buff.md §4.4 / §4.6(已确认,2026-07-13),本页不作任何改动或外推。

前提一 · OI 是什么
未平仓合约数量

不是成交量。成交量数「换了多少次手」,OI 数「场上还有多少张没平的合约」。同一笔成交可以让 OI 增、减或不变——取决于双方是在开新仓还是在平旧仓。

前提二 · ΔOI 的符号
OI↑ = 新仓;OI↓ = 平仓

OI 上升 = 净新增合约 = 新资金进场;OI 下降 = 合约被注销 = 旧仓在离场(主动平仓或被强平)。ΔOI 只告诉你「进场还是离场」,不告诉你方向。

前提三 · 价格补上方向
谁是主动方

价格是「谁更急」的裁决书。把 ΔOI(进场/离场)和价格方向(涨/跌)叉乘,才知道对手方是谁——这正是牌 B 接飞刀前必须回答的问题。

OI ↑ 新仓进场 · 两格都是硬 veto
OI ↓ 旧仓离场 · 两格都是正签名
价涨 白
—
新多进场 涨 + OI↑
新钱在做多推价格上去。上涨有燃料——对手方是刚进场的趋势资金,不是正在离场的旧仓。
牌 A 顺风确认 ⛔ 牌 B 做空 veto
—
空头回补 涨 + OI↓
价格在涨,但没有新多进场——推价格的是空头在认赔平仓。空头平完就没人推了,这是无新赞助的上涨。
牌 A 警惕衰竭 ＋ 牌 B 做空正签名(软)
价跌 蓝
—
新空进场 跌 + OI↑
下跌有推手:新钱在做空。你若此时接多,对手方是刚进场的趋势资金,不是正在离场的旧仓——文档原话:「接刀死法中最机械可辨的一种」。
⛔ 牌 B 做多 veto(硬规则)
—
多头清算投降 跌 + OI↓
价格在跌,但没有新空进场——砸盘的是多头在被强平/割肉离场。卖压来自正在消失的仓位,清算完就卖光了。
＋ 牌 B 做多正签名(软)

格内百分比为本页 500 根真实数据的实测占比(纯符号口径,不含门限)· 牌 A=顺势回踩(频率引擎),牌 B=极值反转(右尾引擎,接飞刀者)

注意左右两列各自同质:OI↑ 那一列的两格都是硬 veto(新仓进场=对手方是趋势资金),OI↓ 那一列的两格都是正签名(旧仓离场=对手方正在消失)。这个领域巧合是 V4 设计的支点——把 ΔOI 符号交给零轴位置,零轴上方自动成为「危险区」、下方成为「衰竭区」,四状态无需靠四种颜色区分。

接入总原则§4.6
OI 是确认/否决调制器,不进加分维度。它的含义随价格上下文翻转——同样的 ΔOI 在不同价格方向下含义相反。含义条件依赖的变量不能当固定符号的加分项,只能作为牌型内的条件项。这条直接决定了面板的编码:ΔOI 不能单独着色,必须与价格方向叉乘后才有语义。
反签名 veto硬规则
牌 B 做多遇「跌+OI↑」、牌 B 做空遇「涨+OI↑」——直接否决,无条件、无例外。这是全套规则里唯一的硬规则,面板必须让它压倒一切地可读。
正签名软加分
牌 B 做多的「天量 + OI 骤降」(清算投降)、牌 B 做空的「涨+OI↓」(回补衰竭)只加分、不设必要。设为必要会在 OI 读数模糊的场次砍掉 B 类频率,损失未量化前不上硬约束。(「天量」的 RVOL 阈值仍待议——本面板的 RVOL 只显示、不参与判定。)
不对称面板的设计约束
veto 是硬规则、正签名只是软加分——策略本身是不对称的,面板也必须不对称。旧版给四个状态相同的视觉权重,这是编码层面的失真,而不只是「不好看」。V4 用「冗余通道数」实现这个层级:veto 占 4 个通道,正签名 2 个,噪声 0.25 个。
只看符号量纲无关
各交易所 OI 单位不同(币安 USDT 本位=币,OKX=张),因此判定只用 ΔOI 的正负号,不做跨所水平值聚合。读数必须用币本位——USD 计价会把价格机械乘进去(§4.6 对账:ETH 聚合 OI 的 USD 口径半年 −38%,币本位实际 +14%,结论相反)。

面板要回答的问题,一句话:「这波行情是新仓推的,还是旧仓平的?」——新仓推的下跌不能接刀(硬 veto),旧仓平的下跌才是投降(软加分)。整个 V4 设计就是把这个判断做成 3 秒可读。

04合成:最终落地方案 V4

V4 不是第四个平行变体,而是三方设计提案(交易员工作流 / 可视化通道理论 / TradingView 生态惯例)收敛后的合成:V1 的方向柱升级为 z 标准化纵轴 + 可见门限线,veto 独占背景色雾(全面板最响、最稀有的通道),上下沿事件车道用形状区分硬/软(✕=禁止,◆=加分),左上角双卡状态牌按符号真值裁决——面板可以安静,状态牌不许说谎。

为什么是这个合成

  • 色相=卡:价跌事件(蓝)全部关于 B多(veto 或签名),价涨事件(白)全部关于 B空——两色系统天然按卡分组,绘图层无红绿 CVD 碰撞对(状态牌文字保留红=veto/绿=签名裁决色,沿 monitor-v2 先例)
  • 响度=稀有度×重要性:veto 占 4 通道(色雾+✕+上半区位置+全饱和),签名 2 通道,幽灵柱 0.25 通道,中性=零墨水
  • 真值/降噪解耦:veto 是符号语义硬规则,门限只是显示降噪(候选)。状态牌按符号真值;柱色/色雾/车道按门限。告警维持你已确认的口径(需求7:仅过门限触发)——「为硬 veto 增加真值告警」列为待你裁决的候选项。两套口径,记账期比对
  • 被否决的方案:琥珀色第五色相(破坏套件四色语言,2:1 否决);OI 水平与 ΔOI 同面板(单面板单标度纪律);用 columns/area 画 OI 水平值(histbase 只收静态 input 无法自适应基线,大基数序列被压平——V0 病根之一;对 ±4σ 的 z 序列 histbase=0 反而是正确锚点)

结论:按 V4 重写 Pine 绘图层;逻辑层做一处定向改动——把 f_classify 拆成 stateRaw(纯符号,喂状态牌)与 stateGated(喂柱色/色雾/车道),告警默认维持已确认口径(仅过门限触发)。

V1–V3 作为设计探索保留在本稿中;V4 的每一层都可以在 Pine 里用输入项独立开关(色雾/车道/幽灵柱),关掉全部叠加层就退化为 V3 的静默模式。OI 水平值不再与 ΔOI 抢面板——用 display=display.data_window 的隐藏 plot 从数据窗口读,废除同面板 plotMode 切换(z 轴 ±4 与 OI ~1e5 同轴会把门限线压成零厚度)。ΔOI% 门限模式建议随 V4 删除。8 行 MTF 表降级为可选(默认关),双卡状态牌成为常驻。

全部候选:白/蓝方向色、透明度阶梯(85→0)、色雾浓度、门限默认 k=1.5、z 裁剪 ±4σ,均待你在 TradingView 实图确认后固化。
