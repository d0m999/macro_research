# Serenity 语料清洗报告（2026-09-21）

源包：`Serenity/x-archive/x-2026-09-21/`（抓取 2026-09-21，DOM 深度滚动）
产出：`Serenity/data/clean/posts.jsonl`（1794）、`replies.jsonl`（5067）
原始包保持不动；清洗只新增，不改源。

## 一、诊断结果（清洗前扫描）

| 检查项 | 结果 |
|---|---|
| posts/replies post_id 冲突 | 0 |
| id 重复 | 0 / 0 |
| 空文本 | 0 / 0 |
| DOM 残留（Show more / Translated from / 时间戳行） | 0 命中 |
| 纯链接帖 | 0 |
| **thread_id 跨文件重叠** | **1794/1794（100%）** ← 唯一实质缺陷 |
| in_reply_to_user 为空 | 98（1.9%） |
| in_reply_to_post_id | **全空**（搜索 DOM 无此信息，且未补抓 with_replies） |

结论：语料文本层面很干净（build 时已做空白折叠 + 按作者过滤），无需内容剔除。
唯一实质缺陷是 thread_id：build 用**行号序号**当 thread（`thread-001` 同时出现在两个文件），
无会话语义且跨文件冲突。

## 二、清洗规则（v1）

1. **thread_id 重建**：以 `T-<post_id 后 10 位>` 全局唯一化，消除跨文件冲突。
   - posts：thread_id = 自身帖根（每条原创帖即一个 thread 根）
   - replies：搜索 DOM 拿不到被回复帖 ID → thread_id 退化为自身根，
     并加 `thread_id_is_self_root: true` 标记。
     **真实会话归组请用 `in_reply_to_user` + `created_at` 邻近度**；
     若要恢复真实 thread 根，需补抓 with_replies 页做邻接推断。
2. **lang 标注**（`en` / `zh` / `mixed`）：中文字符占比 >30% 为 zh，>2 个汉字为 mixed。
3. **links 提取**：正则抽取正文中的 `http(s)://…` 与 `t.co/…` 链接（实测仅 1 条——
   X DOM 把外链放在 entities，不在可见文本里，正文级链接极少，不构成蒸馏噪音）。
4. **self_thread 标记**：`in_reply_to_user == @aleabitoreddit`（自己串自己）→ `is_self_thread`（49 条）。
5. **root_in_pkg 标记**：被回复帖是否在包内（当前全 false，因 in_reply_to_post_id 全空）。
6. **表情噪音（v1.1 增补）**：表情占比极低（posts 1.1%、replies 0.7%）；
   **纯表情无文字的回复 6 条已从 clean 版剔除**（`reply-001302/001825/001974/001977/002020/002070`），
   清单在 `dropped-emoji-only-ids.txt`，原始包保留可回溯。图片表情包不在语料内（`media/` 未抓）。
7. **其余不剔除**：`lol`、`How` 这类超短文本是真内容，保留；表情+文字混排的条目保留
   （表情仅装饰，正文有实质内容）。

- 繁简：疑似繁体为主条目仅 ~11/131 条 zh+mixed（粗筛），无系统性繁简混排；
  检索时仍建议双形正则（`電力|电力`）以防漏检。

## 四、复现命令

清洗为一次性内联脚本（未落 .py，遵循「方法写进技能/报告、不留临时脚本」约定）。
核心逻辑：`thread_id = T-<id[-10:]>`；`lang` 按 zh 字符占比；`links` 用
`https?://\S+|(?<![\w/])t\.co/\S+` 提取；不改文本内容、不删行。

## 五、对后续蒸馏的影响
